# vuln-monkey security + correctness review — 2026-07-09

8-agent fan-out (4x Sonnet 5 + 4x Codex/gpt-5.5), one review lane each, findings deduped across both fleets.

**Confidence:** `both` = found independently by Sonnet AND Codex; `one` = single fleet (verified by hand where it mattered).

## Critical / High

### 1. CRIT `executor/runner.ts:50-75` — SSRF: allowlist never resolves DNS — both
`dnsResolve` is imported and never called. Non-IP-literal hostnames fall through to `return true`. `http://127.0.0.1.nip.io/`, or a short-TTL rebinding record, passes the check-time guard; `fetch()` then does its own lookup (TOCTOU) and hits loopback / `169.254.169.254` metadata / internal DNS names.

### 2. CRIT `executor/runner.ts:36-48` — SSRF: IPv6 private ranges unguarded — both
`ipToInt` only parses IPv4 dotted-decimal, so `isPrivateIP` returns false for all IPv6 literals. `http://[::ffff:169.254.169.254]/`, `http://[fd00::1]/` (ULA), `http://[fe80::1]/` (link-local) all pass. `PRIVATE_RANGES` has no IPv6 entries at all.

### 3. HIGH `executor/runner.ts:160-193` — body-read hang, no timeout on the stream
The AbortController timer is cleared as soon as `fetch()` resolves (headers received), but the body-drain loop (`reader.read()`) has no timeout/abort. A target that sends `200` headers then stalls mid-body pins one concurrency slot forever; enough of them and `executePayloads` never resolves. Scan hangs, no error surfaced.

### 4. HIGH `analyzer/prompts.ts:20-58` (+ `runner.ts:50`) — prompt injection from the fuzz target
`endpoint.bodySchema` and `vulnerabilities[].description` are interpolated raw into the LLM prompt (no delimiting), and `parsePayloads` accepts whatever `url` the LLM returns with zero validation. A hostile target poisons its own schema/description text to steer payload generation. Sonnet: emits an attacker-chosen external `url` and, since `isUrlAllowed` does not block arbitrary external hosts, the scanner becomes a confused-deputy HTTP relay. Codex: injection forces analysis to return `[]`, silently suppressing findings. Both reachable.

### 5. HIGH `reporter/terminal.ts:6,63`, `cli.ts:93,138` — ANSI/terminal-escape injection — both
Untrusted `payload.name` / `finding.title` / `endpoint.url` printed via `console.log`/ora with only chalk color codes (chalk does not strip control chars). Malicious spec content carried through the LLM can embed `\x1b[2J\x1b[H` + fake "all clear" text, clearing/repainting the operator's terminal mid-scan and hiding real crash findings.

## Medium

### 6. `analyzer/openai-compat.ts:47` (+ `provider.ts:22`) — cloud API key leaked to local backend — verified
`if (this.apiKey) headers["Authorization"] = Bearer ${apiKey}` is sent to whatever `baseUrl` is set, including `localhost:11434`. `OPENAI_API_KEY=sk-live vuln-monkey --model ollama` ships the real key to the local endpoint/its logs. Worse, `provider.ts:22` only sets the ollama URL `if (!OPENAI_BASE_URL)`, so a pre-set `OPENAI_BASE_URL=api.openai.com` makes `--model ollama` send the target prompt + key to OpenAI instead of running locally.

### 7. `executor/runner.ts:196-215` — secrets persisted unredacted — both
Request `Authorization` header/body and all response headers are copied verbatim into `ExecutionResult`, which flows into the shared JSON/Markdown reports. Reflected `Set-Cookie`, echoed `Authorization`, token-bearing `Location`, and the input's own bearer token all land unredacted in output meant to be shared.

### 8. `executor/runner.ts:166-169` — oversized response skipped → false negative — both
When `content-length > MAX_RESPONSE_BYTES` the body is replaced with a placeholder and never read; classification becomes `pass`. A `>1MB` error page (e.g. a Python stack-trace dump) is a real leak silently dropped. The unconsumed stream is also never `.cancel()`d (contrast the truncation path), leaking the socket.

### 9. `reporter/markdown.ts:24-35` — markdown/HTML injection into shared reports — both
`payload.method`/`payload.url`/name interpolated into inline code spans with no escaping (unlike `response.body` which escapes fences). A backtick or raw HTML in an attacker-influenced value breaks out of the span → injected sections / stored injection in client-facing `.md`.

### 10. `analyzer/cli-provider.ts:14,24` — flags after `--` are inert — both
`["-p", "--", prompt, "--output-format", "text"]` and `["exec", "--", prompt, "--full-auto"]`. `--` terminates option parsing, so `--full-auto` / `--output-format` / the `-p` value are treated as positionals — never applied. Combined with immediate `stdin.end()`, CLI-provider backends stall to the 180s timeout or analyze the wrong text.

### 11. `parser/openapi.ts:45` — spec fetch has no timeout/size cap — both
`parseOpenAPIFromURL` does `fetch(url)` + `response.json()` with no AbortSignal, timeout, or size limit — hardening applied to fuzzed requests but not to fetching the spec that seeds the run. An adversarial `--spec` endpoint (the tool's own threat model) hangs or OOMs the CLI before any payload fires.

### 12. `parser/openapi.ts:31` — path parameters emitted literally — both
`url = ${baseUrl}${path}` leaves `/users/{id}` untemplated; downstream fetch sends `/users/%7Bid%7D`. Parameterized endpoints are fuzzed on the wrong route and reported clean. `operation.parameters` is never read; every endpoint gets `headers:{}`, `auth:{type:"none"}`.

### 13. `parser/curl.ts`, `parser/openapi.ts:22` — parser silently drops request semantics — both
- `-XPOST` fused form not matched → method stays GET (curl.ts:58).
- `-u/--user` basic auth skipped → `auth:none`, no Authorization header.
- `-G` query mode ignored and `-d` forces POST → wrong method + body.
- `$ref` request bodies ignored → `bodySchema` omitted, body issues missed.
- repeated `-d` overwrites earlier body parts.
A security tool quietly testing the wrong method / auth / body.

### 14. `parser/openapi.ts:17` — one `null` path item aborts the whole spec — one
`pathItem[method]` with no null guard: `{"paths":{"/foo":null}}` throws, uncaught in `parseOpenAPIFromJSON`, discarding every other endpoint in the spec. Caught by cli.ts outer try/catch (no process crash) but zeroes scan coverage.

### 15. `cli.ts:168-189` — partial analyze failure counted as success — one
`provider.analyze(/admin)` throws, `/health` succeeds → exit 0 and "Endpoints scanned: 2", even though `/admin` got zero fuzzing. Coverage lie. Also the JSON-write catch silently discards the fact the markdown report already wrote.

## Root cause behind 4, 9, 13 (and an LLM-header crash)
`AttackPayloadSchema` (zod) is defined in `types.ts` but never `.parse()`d on LLM output. `parsePayloads` also casts `item["headers"]` to `Record<string,string>` without checking values are strings (non-string → TypeError at fetch time). Enforcing `safeParse` at the analyzer boundary + stripping control chars from `name`/`url`/`method` closes the injection/validation class in one place.
